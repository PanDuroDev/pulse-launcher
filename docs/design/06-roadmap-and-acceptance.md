# 06 — خريطة التنفيذ ومعايير القبول

> هذه الوثيقة لا تنفّذ شيئاً. هي ترتيب العمل بعد الموافقة، مع بوابة قياس تمنع
> التراجع إلى التكتّم.

---

## 1. مبدأ الترتيب

1. **الرموز أولاً** (ألوان، أحجام، مسافات): تغييرها لاحقاً بعد إعادة بناء الشاشات
   يعني إعادة العمل مرتين.
2. **المكوّنات المشتركة ثانياً** (`PageFrame`، `Button`، `Field`): تمنع تكرار
   الحلول في كل شاشة.
3. **الشاشات ثالثاً**، من الأكثر ازدحاماً إلى الأقل: الموسيقى، الرئيسية،
   الإعدادات، ثم الباقي.
4. **التنظيف أخيراً**: حذف الأنماط الميتة والنسخ القديمة.

كل مرحلة PR مستقل، قابلة للمراجعة والتراجع وحدها.

## 3. بوابة القياس

### 3.1 سكربت `scripts/design-census.mjs`

يفحص `src/renderer/src` ويطبع JSON + جدولاً، ويفشل عند تجاوز أي حد:

| القاعدة | الحد |
|---|---:|
| أحجام خط مميزة | ≤ 6 |
| أصغر خط | ≥ 12px |
| شفافيات نص مسموحة | `{48, 64, 80, 100}` فقط |
| أنصاف أقطار مميزة | ≤ 3 |
| مدد حركة مميزة | ≤ 2 |
| شدات ضباب | ≤ 1 |
| توهّجات (`0 0 …px`) | 0 |
| صفوف مكتبة | ≤ 3 |
| أدوات شريط علوي | ≤ 4 |
| تلميحات دائمة | ≤ 3 |
| `px-[…vw]` | 0 |
| هدف قابل للتركيز بعرض **أو** ارتفاع أقل من 44px في `src/renderer/src` | 0 |

يُقاس الحجم بصندوق الهدف الفعلي (`getBoundingClientRect`)، ويُعدّ الهدف فاشلًا
إذا كان `width < 44 || height < 44` — لا يكفي أن يتجاوز أحد البعدين الحد.

يُنشأ في **P0.0** قبل أي تغيير بصري ويُضاف كـ`npm run design:check`. آلية
الوضعين صريحة عبر علم على سطر الأوامر:

| الأمر | السلوك | رمز الخروج |
|---|---|---:|
| `npm run design:check` (= `--warn`) | يطبع كل تجاوز كتحذير مع ملف:سطر | **0** |
| `node scripts/design-census.mjs --strict` | أي تجاوز = فشل | **1** |

`package.json` يشغّل الوضع التحذيري في P0–P2، وتُبدَّل النصوص في P3 إلى
`--strict` لتصبح بوابة CI إلزامية. العلم الافتراضي تحذيري كي لا تتعطّل PRات
المراحل المبكرة، والانتقال إلى `--strict` تغيير مقصود في PR واحد. قاعدة الحجم
تشمل **كل هدف تفاعلي/قابل للتركيز** في `src/renderer/src` (أزرار،
`useFocusable`، `role="button"`، حقول الإدخال، مقابض التمرير)، وليس الرئيسية
وحدها؛ تُستثنى النصوص غير التفاعلية فقط. النسخة الأولى تقيس ما يمكن قياسه من
الرموز؛ قواعد الصفوف والأدوات والتلميحات تُضاف مع P1.

#### 3.1.1 البوابة التشغيلية لقياس الـDOM الحيّ

`design-census.mjs` سكربت ساكن: يقرأ الملفات ولا يشغّل الواجهة، لذلك **لا
يستطيع** قياس `getBoundingClientRect` بنفسه. التفصيل مقصود، لا مؤقت:

| | |
|---|---|
| البوابة الساكنة (`design:check`) | تُحسب من الرموز: أعداد الخطوط، الشفافيات، الأنصاف، المدد، الصفوف، الأدوات. تفشل على أي رقم خارج الحد، لكنها **لا تدّعي** أنها تقيس الحجم الفعلي |
| البوابة الحيّة (`npm run design:dom`) | **سكربت منفصل يُنشأ مع P3.0** يشغّل التطبيق المبني عبر بروتوكول DevTools (نفس طريقة `D:\Temp\User\opencode\phase8-smoke.mjs`) ويقيّد كل هدف |

قواعد القياس الحيّ، مكتوبة قبل التنفيذ كي لا تُخترع لاحقاً:

- **الـviewport**: 1920×1080 و1280×720، `deviceScaleFactor` 1، ثم تكرار 1.25 و1.5 لمحاكاة تكبير Windows. كل حالة تُقاس منفصلة، ويُسجَّل التكبير مع كل مخالفة.
- **اكتشاف الأهداف**: كل عنصر يطابق `button, [role="button"], input, select, textarea, a[href], [data-focus-key]` — نفس ما يقوله معيار الحجم أعلاه حرفياً، لا اجتهاد.
- **الإخفاء**: يُستثنى ما `offsetParent === null` أو `getClientRects().length === 0` أو `visibility: hidden`، وتُستثنى العناصر داخل طبقة غير نشطة (تفاصيل مغلقة، قائمة طاقة مغلقة، لوحة إعداد مغلقة).
- **الأهداف المتحركة**: تُقاس بعد استقرار الحركة (طلب إطارين متتاليين)، لا في منتصف `transform` تحجيم.
- **الفشل**: `width < 44 || height < 44` بأي بُعد، من `getBoundingClientRect` بعد التحويل.
- **المخرجات**: `design-dom-report.json` + ملخص في الطرفية، ورمز خروج 1 عند أي مخالفة.

**الحاجز الزمني:** لا تُفعّل `--strict` على البوابة الساكنة كبوابة CI قبل أن
تعمل البوابة الحيّة، لأن اعتماد بوابة ساكنة على قياس حيّ لا يوجد بعد يعني
ثقة زائفة. حتى ذلك الحين يبقى البند «44px» **شرط قبول يدوي** يُتحقّق منه في
مصفوفة اللقطات (§3.2).

### 3.2 مصفوفة اللقطات

| العرض | لماذا |
|---|---|
| 1280×720 | الحد الأدنى — يفشل اليوم |
| 1920×1080 | الحالة الأساسية |

| تكبير Windows 125% و150% | الحالة الشائعة على أجهزة التلفاز |

## 4. معايير القبول النهائية

### أرقام

- [ ] 6 أحجام خط كحد أقصى، وأصغرها 12px.
- [ ] 4 مستويات شفافية نص، و0 نص تحت **4.8:1** (قياس تباين فعلي، لا شفافية فقط).
- [ ] 3 أنصاف أقطار، 2 مدد حركة، ظل واحد، ضباب واحد.
- [ ] 0 توهّج، و0 تلوين chrome بلون لعبة.
- [ ] الرئيسية: ≤ 3 مناطق و≤ 20 هدفًا افتراضيًا.
- [ ] الموسيقى: ≤ 12 هدفًا ثابتًا، وصف أدوات أعلى القائمة (لا عمود جانبي)،
      وبلا قصّ عند 720p، والتكرار وتبديل الـOverlay يعملان من قائمة «⋯ خيارات».
- [ ] الإعدادات: لوح بعمودين (فهرس + لوحة)، ≤ 8 صفوف في اللوحة، 5 أقسام ظاهرة
      بلا قصّ عند 1080p، وبحث يرشّح الفهرس.
- [ ] لا صفحة كاملة لأي شاشة ثانوية: الإعدادات والتفاصيل والإضافة والبحث ومدير
      الملفات تُفتح كألواح فوق وجهة مركّبة، والمكتبة لا تُفكّ عند الفتح.
- [ ] لا زر رجوع في أي لوح؛ الإغلاق بـ`✕`/`Esc`/`◯` ويعيد التركيز إلى الفاتح.
- [ ] الـOverlay: كل الأزرار **≥ 44px**، والكتم عبر `M` وزر الصوت في الموسيقى
      متزامن.
- [ ] الإقلاع: وسيط 5 قياسات من `boot:start` إلى `boot:ready` ≤ **1.2s**،
      ويُكتب `boot:ready` بعد جاهزية الشاشة الرئيسية فعليًا (طابعا `boot:start`
      و`boot:ready` في `logs/main.log`)، والتخطي يستجيب خلال **100ms** بعد
      600ms.

### نوعية

- [ ] لا وظيفة مفقودة: كل عنصر محذوف له بديل موثّق في ملف 05.
- [ ] التنقّل بالعصا ولوحة المفاتيح يعمل على كل شاشة معدّلة.
- [ ] `prefers-reduced-motion` يحترم في كل حركة جديدة.
- [ ] لا نص عربي مشوّه: لا `uppercase` ولا تتبّع مفرط على نصوص المحتوى.
- [ ] الشاشات الجديدة تخلو من جمل تعليمية داخل الواجهة.

## 5. المخاطر والمعالجة

| الخطر | الاحتمال | المعالجة |
|---|---|---|
| كسر مفاتيح التركيز الثابتة | متوسط | عدم لمس `focusKey` أثناء التبسيط؛ مراجعة يدوية لكل شاشة |
| قصّ عند 720p | مرتفع | 720p شرط قبول لا حالة حدّية؛ لقطات إلزامية |
| فقدان تباين فوق الملصقات الفاتحة | متوسط | scrim إلزامي ≥ 0.72 واختبار على 5 أغلفة فاتحة |
| إزالة صفوف مربكة للمستخدم الحالي | متوسط | مرشّحات واضحة + حالة فارغة تشرح مكان المفضلة |
| استبدال جماعي بالبحث/الإحلال يكسر أنماطاً شرطية | مرتفع | PR لكل ملف/مجموعة، ومراجعة فرق لا استبدال شامل |
| تكرار العمل إذا تأخّرت الرموز | متوسط | P0 قبل كل شيء |
| تعارض مع i18n/RTL | منخفض الآن | الخطة تقلّل التتبّع والأحرف الكبيرة أصلاً |

## 6. خارج النطاق

- إعادة تصميم الهوية أو الشعار أو الكرة.
- إضافة ميزات جديدة (on-screen keyboard، فلاتر موسيقى، توقيع، تحديث تلقائي).
- تغيير بنية IPC أو محرّك التركيز.
- ترجمة الواجهة أو دعم RTL — تُذكر كقيد مستقبلي، ولا تعالج هنا.

## 7. ما تحتاجه من المنتج

1. الموافقة على تحويل الأقسام (Favorites/Steam/Epic/Local) إلى **مرشّحات**.
2. الموافقة على دمج «All» في الموسيقى ضمن المرشّحات.
3. الموافقة على نقل Add/Refresh من الشريط العلوي إلى شريط المكتبة.
4. الموافقة على إخفاء التلميحات بعد فترة قصيرة وظهورها عند الطلب.
5. الموافقة على شكل الـOverlay (4 أزرار 44px، بلا كتم مرئي مع إبقاء `M`).

بدون هذه الموافقات تبقى بقية الخطة صالحة، وتُستثنى البنود الخمسة فقط.
